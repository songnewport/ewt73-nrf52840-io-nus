# EWT73 / nRF52840 蓝牙项目阶段成果报告

日期：2026-05-17

## 一句话总结

我们已经把 nRF52840 从单纯测试板，推进到可以演示的智能分流器蓝牙主控原型：它可以读取电压、电流、温度和开关状态，可以通过手机 App 配对、连接、查看实时数据，并能通过加密蓝牙通道控制 LED，已经具备替代原 PB3F 蓝牙模块并继续开发正式产品的基础。

## 已完成的核心成果

### 1. 完成 PB3F 替代方案的原型验证

原项目中使用 PB3F 蓝牙模块，通过串口和 STM32U575 通信。我们已经完成了 nRF52840 替代 PB3F 的第一版方案验证：

- nRF52840 可以作为独立蓝牙模块工作。
- 保留串口通信思路，便于后续继续和 STM32U575 对接。
- 模拟了 PB3F 的典型使用流程：扫描设备、连接目标设备、断线后重连、通过串口向主控传递蓝牙状态和数据。
- 验证了手机端和 PC 终端之间的透传通信能力。

这个阶段证明：后续正式项目中，使用 nRF52840 替换 PB3F 是可行的，而且可控性更好。

### 2. 完成 E73 / EWT73 测试板硬件 bring-up

我们完成了 EBYTE E73 / EWT73 nRF52840 测试板的基础硬件验证：

- 确认 J-Link/SWD 烧录流程可用。
- 确认板上 LED、按键、ADC、I2C 均可由固件控制和读取。
- 确认 BLE 广播、连接、断开、重连流程可运行。
- 建立了可重复烧录、可重复测试的本地开发环境。

这一步把“模块能不能用”的风险基本消除了。

### 3. 完成 ADC 和开关状态采集

测试板已经能够读取：

- AIN1 电压
- AIN4 电压
- SW1 / SW3 / SW4 开关状态
- PAIR 按键短按、5 秒长按、10 秒长按事件

典型已验证数据：

```text
AIN1 ~= 3340 mV
AIN4 ~= 0 mV
开关按下和释放可以显示 1 / 0 变化
```

这个能力为后续读取外部模拟信号、开关信号和用户操作打下基础。

### 4. 完成 INA228 传感器接入

已接入并验证 INA228 电压/电流/温度传感器。

硬件连接：

- SDA：P1.11
- SCL：P1.10
- I2C 地址：0x40

典型已验证数据：

```text
VBUS ~= 3327-3329 mV
INA228 温度 ~= 21.5 C
nRF52840 内部温度 ~= 22.0 C
```

这说明 nRF52840 已经可以读取正式智能分流器项目所需的关键传感器数据。

### 5. 完成自定义 BLE UUID 测试服务

我们在 nRF52840 上建立了一个自定义 GATT 服务，用于未来正式 App 的基础框架。

当前服务包含：

- 实时数据 UUID：发送电压、电流、温度、SOC 等公开数据。
- LED 控制 UUID：通过加密写入控制 P19 LED。
- 设备状态 UUID：显示配对状态、连接状态、固件版本、通知状态等。
- 安全信息 UUID：通过加密读取触发手机系统配对，并读取设备序列号。

当前 demo 序列号：

```text
DEMO-170526
```

当前固件版本：

```text
0.2.7-SECURE-READ-DEMO
```

这个结构已经接近未来正式产品 App 的 BLE 框架。

### 6. 完成 Android 测试 App

我们做了一个 Android 测试 App，用来替代难读的通用蓝牙串口工具。

App 当前可以：

- 扫描并显示测试设备。
- 连接 nRF52840。
- 通过系统弹窗完成蓝牙配对。
- 显示实时电压、电流、温度、SOC。
- 显示加密读取到的序列号和固件版本。
- 显示设备状态。
- 控制 P19 LED 开关。
- 清除 App 端保存的设备记录。
- 在固件更新后，引导用户去 Android 系统设置里清除旧蓝牙绑定。

这让演示过程从“看串口日志”变成了“打开 App 看数据和控制设备”，更适合给客户或内部管理层展示。

## 关键问题和解决结果

### 配对流程从混乱变为稳定

早期问题：

- 手机配对弹窗出现两次。
- 有时要求 PIN/passkey。
- 有时一连接就断开。
- 固件升级后旧绑定和新固件不匹配，重新连接困难。

最终处理：

- 遵循 Nordic / Zephyr 官方机制，不再自己实现配对状态机。
- 配对只由加密 UUID 读取触发。
- 硬件 PAIR 按键只负责打开 60 秒配对窗口。
- 固件不再主动重复请求安全等级，避免和 Android 系统配对流程冲突。
- Android App 同一连接只触发一次 secure read。

当前结果：

- 配对弹窗已经从两次变成一次。
- 首次安装 App 后，可以通过加密读取触发系统配对。
- 已配对后再次连接，可以直接进入主页面。
- 固件更新后，Android 能引导用户去系统设置清除旧绑定。

### LED 控制从不稳定变为稳定

早期问题：

- P19 LED 在未连接或连接后会随机短闪。
- App 控制 LED ON/OFF 时偶尔需要按两次。

根因：

- P19 同时被当作“业务 LED”和“通信活动指示灯”使用。
- LED 写入成功后，状态字段没有立即刷新，App 有时读到旧状态。

最终处理：

- P19 只作为 App 控制 LED，不再做通信短闪。
- LED 写入成功后立即刷新设备状态。

当前结果：

- P19 随机短闪已修复。
- LED ON/OFF 控制已稳定。

## 当前可演示内容

现在可以向老板或客户演示：

1. 手机 App 扫描并发现设备 `JUSTIN_SHUNT_TEST`。
2. 按住设备 PAIR 键进入配对窗口。
3. 手机点击设备后弹出一次系统配对确认。
4. 配对后 App 显示实时数据。
5. App 显示加密读取到的设备序列号和固件版本。
6. App 控制 P19 LED 开关，证明加密控制链路可用。
7. 断开后重新连接，设备可以恢复连接并显示数据。

## 对项目的意义

### 对硬件方案的意义

nRF52840 可以承担原 PB3F 蓝牙模块的功能，并且扩展能力更强：

- 不只是透传模块。
- 可以直接读取传感器。
- 可以做安全配对和授权。
- 可以支持后续正式 App。
- 可以减少对 AT 命令模块的依赖。

### 对软件方案的意义

当前代码已经明确采用 Nordic / Zephyr 官方框架：

- 使用官方 BLE 初始化流程。
- 使用官方 GATT characteristic 权限触发配对。
- 使用官方 settings 子系统保存 bond。
- 使用官方连接、安全、配对回调。
- 避免自定义 BLE 安全系统。

这对后续长期维护、SDK 升级和产品化非常重要。

### 对演示和客户沟通的意义

现在已经不再只是串口日志或实验代码，而是有了：

- 可烧录固件
- 可连接手机 App
- 可显示数据
- 可触发配对
- 可验证加密控制
- 可解释的产品流程

这已经可以作为智能分流器蓝牙方案的早期 demo。

## 仍需继续完善的事项

当前 demo 已经可用，但还不是最终产品。后续建议：

1. 将 PB3F 替代项目和 EWT73 传感器 demo 进一步合并，形成面向 STM32U575 的正式通信协议。
2. 明确正式产品的 BLE UUID、数据格式和版本管理策略。
3. 将 demo 序列号 `DEMO-170526` 改为生产烧录或工厂配置的真实序列号。
4. 完善 App 首次使用页面，让普通客户更容易理解“按住设备配对键再连接”的流程。
5. 增加断线重连、低电量、传感器异常等产品级提示。
6. 做更长时间稳定性测试，包括反复断电、反复连接、不同 Android 手机兼容性测试。
7. 后续如需要 iPhone 支持，应尽早做 iOS BLE 流程验证。

## 当前结论

本阶段已经达成关键目标：

- nRF52840 替代 PB3F 的方向可行。
- E73 / EWT73 测试板硬件和传感器已经打通。
- INA228、ADC、开关、内部温度均可读取。
- BLE 自定义 UUID、加密读取、加密写入、配对和重连框架已经建立。
- Android demo App 已经可以用于内部演示。

建议将当前版本作为“可演示基线版本”保存，后续在此基础上进入正式产品通信协议和 App 体验设计。
